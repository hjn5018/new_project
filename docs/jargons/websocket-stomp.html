🔌 WebSocket vs STOMP 프로토콜 심층 분석

TCP 3-Way Handshake와 HTTP Upgrade를 통한 전이중 파이프(WebSocket) 및 Pub/Sub 메시지 브로커 규격(STOMP) 비교

💡 1. WebSocket과 STOMP의 핵심 동작 메커니즘

🌐 WebSocket (전송 계층 프로토콜)

  • 핸드셰이크 과정: 1단계 TCP 3-Way Handshake(SYN, SYN-ACK, ACK) ➔ 2단계 HTTP Upgrade 요청(Upgrade: websocket, 101 Switching Protocols).
  • 양방향 파이프(Full-Duplex): 연결이 한번 수립되면 서버와 클라이언트가 연결을 끊지 않고 실시간으로 데이터를 주고받음.
  • 한계: 순수 전송 프로토콜(Transport)이므로 메시지 형식(규격)이 없음. 단순 문자열/바이너리만 오가므로 개발자가 직접 데이터 파싱 및 라우팅 로직을 하드코딩해야 함.

📬 STOMP (응용 서브 프로토콜)

  • 정의: WebSocket 통신 위에서 동작하며, HTTP처럼 COMMAND, Headers, Body 표준 규격을 정의하는 상위 프로토콜.
  • Pub/Sub 브로커 연동: SUBSCRIBE /topic/chat/101, SEND /app/chat.send 명령어로 채널 구독 및 브로드캐스팅 지원.
  • Spring & Redis 연동: Spring Boot @MessageMapping 및 다중 서버 확장을 위한 Redis Pub/Sub 메시지 브로커와 손쉽게 결합.

🚀 3. Spring Boot & Redis Pub/Sub 실무 연동 구조

서버 1번에 접속한 유저 A가 채팅을 치면, Spring 백엔드가 Redis Channel(Topic)로 메시지를 발행(Publish)하고, 서버 2번에 접속한 유저 B에게 Redis가 이벤트를 전달하여 여러 대의 서버로 Scale-Out된 실시간 채팅망을 구축합니다. 

// [Spring Boot Controller] STOMP 메시지 수신 및 Redis 브로드캐스팅
@MessageMapping("/chat.send")
public void sendMessage(@Payload ChatMessage message) {
    // 1. DB에 채팅 기록 저장
    chatService.saveMessage(message);
    
    // 2. Redis Topic으로 발행 ➔ 모든 서버에 분산 전파
    redisTemplate.convertAndSend("chat-room-" + message.getRoomId(), message);
}
