🔄 Kafka CDC (Change Data Capture) 입문 & 파이프라인 용어 사전

이중 작성(Dual Write) 문제 해결부터 Binlog, WAL, Avro, Sink 등 CDC 핵심 용어 및 DB 설정 가이드

🌱 1. CDC가 왜 필요한가요? (이중 작성의 악몽)

❌ 전통적인 방식: 앱에서 직접 2군데 쓰기 (Dual Write 문제)

회원이 닉네임을 변경할 때 백엔드 스프링 앱에서 1) MySQL UPDATE ➔ 성공 후 2) Elasticsearch 색인 API 호출 ➔ 네트워크 장애로 실패! 가 발생하면, DB에는 새 이름이 있는데 검색창에는 옛날 이름이 뜨는 치명적 데이터 불일치가 발생합니다.

✅ CDC 방식: DB의 'CCTV 일기장'을 감시하기

앱은 오직 MySQL DB에만 평소처럼 저장하고 끝냅니다. 대신 CDC 엔진(Debezium)이 DB의 변경 로그(Binlog/WAL)를 실시간으로 테일링(훔쳐보기)하여 Kafka 이벤트로 발행해 Elasticsearch, Redis, Snowflake로 안전하게 자동 배달합니다.

📝 Debezium이 캡처한 변경 이벤트 JSON 페이로드 실제 예시

{
  "payload": {
    "before": { "id": 101, "username": "hong_old", "email": "hong@test.com" },
    "after": { "id": 101, "username": "hong_new_king", "email": "hong@test.com" },
    "op": "u", // 'c'=Create, 'u'=Update, 'd'=Delete
    "ts_ms": 1723351200000
  }
}

📖 3. [용어 사전] CDC 파이프라인 필수 핵심 용어 해설

📘 Binlog (Binary Log)
MySQL이 데이터 추가/수정/삭제 등 테이블 변경 사항을 시간순으로 디스크에 기록하는 이진 로그 파일.
📘 WAL (Write-Ahead Logging)
PostgreSQL이 트랜잭션 무결성을 위해 데이터 변경 내역을 디스크에 먼저 기록하는 사전 로그 파일.
🔍 로그 테일링 (Log Tailing)
tail -f처럼 파일 끝에 새로 추가되는 로그 라인을 실시간으로 지속 감시하며 읽어내는 기법.
📬 Kafka Topic
Kafka 안에서 데이터가 주제별(예: dbserver1.users)로 분류되어 분산 저장되는 메시지 채널.
📦 Apache Avro
JSON보다 훨씬 가벼운 바이너리 직렬화 포맷. 데이터 스키마를 중앙 Registry에 분리하여 전송량을 80% 압축.
🎯 Target Sinks
Kafka Topic에 모인 변경 데이터를 최종적으로 소비하여 저장하는 목적지 시스템들 (Elasticsearch, Redis 등).
❄️ Snowflake & DW (Data Warehouse)
DW는 대규모 비즈니스 분석용 빅데이터 저장소이며, Snowflake는 대표적인 클라우드 초고속 분산 DW입니다.

⚙️ 4. [질문 해결] Binlog와 WAL은 DB에 기본적으로 켜져 있나요?

DB 설치 후 아무런 설정을 하지 않아도 기본으로 켜져 있는지, 일반 사용자가 SQL로 어떻게 확인하는지 완벽히 정리합니다.

🐬 MySQL (Binlog 기본값 & 확인)

• 기본 적용 여부: MySQL 8.0부터는 기본(Default)으로 켜져 있습니다(ON).
• CDC 필수 설정: Debezium이 변경 전/후 데이터를 다 읽으려면 binlog_format = ROW 및 binlog_row_image = FULL 설정이 필요합니다. 

-- [일반 유저의 Binlog 확인 쿼리]
SHOW VARIABLES LIKE 'log_bin';
-- 결과: Value = ON (활성화 상태)

SHOW VARIABLES LIKE 'binlog_format';
-- 결과: Value = ROW (행 단위 변경 기록)

🐘 PostgreSQL (WAL 기본값 & 확인)

• 기본 적용 여부: 서버 비정상 종료 시 복구(Crash Recovery)를 위해 기본으로 항상 켜져 있습니다.
• CDC 필수 설정: 기본 wal_level은 replica이므로, Debezium CDC 연동을 위해서는 postgresql.conf에서 wal_level = logical로 변경해주어야 합니다. 

-- [일반 유저의 WAL 레벨 확인 쿼리]
SHOW wal_level;
-- 결과: logical (CDC 복제 가능 상태)
