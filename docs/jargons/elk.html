📊 ELK 스택 (Elasticsearch, Logstash, Kibana) 파이프라인

대규모 분산 서버 환경에서 비정형 로그가 수집, 파싱, 역색인 검색, 시각화되는 4단계 아키텍처 및 데이터 변환 과정

🖥️ 1. ELK 로깅 파이프라인 4단계 시각화 흐름도

1. Beats / Filebeat
Spring Boot 서버에 상주
텍스트 로그 경량 수집
➔
2. Logstash
Grok 필터 데이터 가공
JSON 구조화 변환
➔
3. Elasticsearch
역색인(Inverted Index)
분산 클러스터 고속 검색
➔
4. Kibana
실시간 에러 대시보드
로그 시각화 & 알람

🔍 2. 각 단계별 상세 역할 & 실제 데이터 변환 과정

1단계: Filebeat가 수집하는 원본 로그 (Raw String)

Spring Boot 앱이 /var/log/app.log 파일에 텍스트 한 줄로 출력한 내용입니다.

2026-08-18 10:30:15.120 ERROR [order-service,trace-9918] 1082 --- [http-nio-8080-exec-1] c.e.OrderService : 결제 승인 타임아웃 오류 발생 userId=8812 amount=50000

2단계: Logstash Grok 필터링 후 구조화된 JSON 데이터

Logstash가 정규식(Grok)으로 파싱하여 검색과 집계가 가능한 필드로 분리합니다.

{
  "@timestamp": "2026-08-18T10:30:15.120Z",
  "log.level": "ERROR",
  "service.name": "order-service",
  "trace.id": "trace-9918",
  "user.id": 8812,
  "payment.amount": 50000,
  "message": "결제 승인 타임아웃 오류 발생"
}

3단계: Elasticsearch의 역색인(Inverted Index) 생성 및 고속 검색

"타임아웃", "8812", "order-service" 등의 단어를 색인 테이블에 매핑하여 수십억 건의 로그 중에서도 0.05초 만에 검색해냅니다.

4단계: Kibana 대시보드 시각화

"최근 1시간 동안 order-service의 ERROR 로그 건수"를 시계열 꺾은선 그래프로 그리고 담당자 슬랙으로 경고 알람을 발송합니다.
