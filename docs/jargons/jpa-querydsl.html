🚨 1. 문자열 쿼리(JPA)의 치명적 함정과 QueryDSL의 컴파일 검증

❌ JPA / JPQL : 단순 문자열(String) 방식
자바 컴파일러는 큰따옴표("...") 안의 내용을 검사하지 못합니다! 
// ⚠️ 테이블명, 컬럼명, 문법에 오타가 있어도
// Java 컴파일러는 단순 String으로 인식하여 【컴파일 통과 (빌드 성공)】
String jpql = "selecct m from Memmbeerr m " +
              "where m.userrname = :name";

// 💥 실제 사용자가 결제/조회 버튼을 누르는 순간!
// 서버에서 런타임 500 에러(QuerySyntaxException) 폭발!
List<Member> result = em.createQuery(jpql, Member.class)
    .setParameter("name", "홍길동")
    .getResultList();
✅ QueryDSL : 자바 객체 & 메서드 체이닝
엔티티를 스캔하여 생성된 QMember 클래스의 필드를 직접 참조합니다! 
// ✅ Annotation Processor가 생성한 Q클래스 사용
QMember m = QMember.member;

// 만약 m.userrname 처럼 오타를 치면?
// 🔴 IDE에서 즉시 빨간 줄 표시 + 컴파일 에러(Cannot resolve symbol)!
// 빌드 자체가 중단되므로 버그가 배포될 위험 0%!
List<Member> result = queryFactory
    .selectFrom(m)
    .where(
        m.username.eq("홍길동"),
        m.age.gt(20)
    )
    .fetch();

⚙️ 2. QueryDSL의 컴파일 타임 검사는 어떻게 가능한가요?

1. 개발자가 @Entity public class Member { private String username; } 엔티티를 작성합니다.
2. 프로젝트 빌드(Build) 시 QueryDSL APT(Annotation Processing Tool) 플러그인이 동작하여 QMember.java라는 자바 메타모델 클래스를 자동 생성합니다.
3. QMember.java 안에는 public final StringPath username = createString("username"); 같은 실제 자바 객체 필드가 들어있습니다.
4. 개발자가 코드를 칠 때 자바 컴파일러는 일반 자바 변수/메서드 유효성을 검사하듯이 오타와 타입 불일치(숫자 필드에 문자열 비교 등)를 100% 컴파일 단계에서 검증합니다.

📊 3. JPA(Spring Data JPA) vs QueryDSL 비교표

비교 항목 JPA / Spring Data JPA QueryDSL
관계 및 역할 QueryDSL은 JPA(Hibernate/EntityManager) 위에서 동작하는 SQL 빌더 라이브러리 (대체재가 아닌 상호 보완재)
문법 오류 발견 시점 런타임 (사용자가 API 호출할 때) 컴파일 타임 (코드 작성 및 빌드 시점)
동적 쿼리 작성 문자열 if (name != null) sql += " AND..." 조합으로 가독성 최악 BooleanBuilder 또는 usernameEq() 메서드로 깔끔하게 분리 및 재사용 가능
실무 권장 조합 단순 CRUD (`findById`, `save`, `delete`) 복잡한 조건 검색, 다중 JOIN 페이징, 통계 대시보드 쿼리
