🍃 NoSQL 4대 데이터 모델 심층 비교 및 실무 예시

문서(Document), 키-값(Key-Value), 와이드 컬럼(Wide-Column), 그래프(Graph) 데이터베이스의 아키텍처 및 실제 데이터 모델링 예시

📊 NoSQL 4대 유형별 특징 및 구조 매트릭스

1. Document Store

MongoDB / Couchbase

JSON/BSON 형태의 가변 구조 문서를 통째로 저장. 중첩 객체와 배열 지원이 뛰어나며 가장 범용적인 RDBMS 대안.

2. Key-Value Store

Redis / DynamoDB

Unique Key와 Value를 1:1 매핑. 극도의 초고속 인메모리 읽기/쓰기 성능을 제공하며 세션 및 캐싱에 최적화.

3. Wide-Column Store

Cassandra / ScyllaDB

행(Row)마다 동적인 컬럼 집합을 가지며, 초당 수십만 건의 대규모 분산 쓰기 및 시계열(Time-series) 데이터에 특화.

4. Graph Database

Neo4j / Amazon Neptune

노드(Node)와 간선(Edge/Relation) 형태로 데이터를 저장하여 수직/수평 다단계 관계 탐색을 O(1)에 가깝게 해결.

💡 NoSQL 4대 모델별 실제 데이터 구조 & 쿼리 예시

1. Document Store 예시 (MongoDB 전자상거래 상품 스펙)

의류, 전자기기 등 카테고리마다 속성이 완전히 달라도 테이블 ALTER 없이 유연하게 적재 가능합니다.

// MongoDB Document (JSON / BSON)
{
  "_id": ObjectId("64f8a1..."),
  "name": "맥북 프로 16인치",
  "category": "LAPTOP",
  "price": 3690000,
  "specs": {
    "chip": "M3 Max",
    "ram_gb": 64,
    "ssd_tb": 1
  },
  "tags": ["apple", "macbook", "developer"]
}

2. Key-Value Store 예시 (Redis 로그인 세션 & TTL 캐시)

사용자 토큰 키로 회원 정보를 0.1ms 내에 조회하고 TTL로 자동 만료 처리합니다.

// Redis SET / GET 명령
SET user:session:tk_99a8b1 "{\"userId\": 101, \"role\": \"ADMIN\"}" EX 3600
GET user:session:tk_99a8b1 ➔ {"userId": 101, "role": "ADMIN"}

3. Wide-Column 예시 (Cassandra IoT 센서 시계열 로그)

장비 ID를 파티션 키로 삼고, 타임스탬프를 클러스터링 키로 삼아 초당 수만 건의 센서 데이터를 시계열로 고속 적재합니다.

-- Cassandra CQL (Table & Data Insertion)
CREATE TABLE factory_iot_metrics (
    sensor_id text,
    recorded_at timestamp,
    temperature double,
    humidity double,
    PRIMARY KEY (sensor_id, recorded_at)
) WITH CLUSTERING ORDER BY (recorded_at DESC);

4. Graph DB 예시 (Neo4j 소셜 친구 추천 & 이상 거래 탐지)

"홍길동의 친구들이 가장 많이 팔로우한 사람 5명 추천" 쿼리를 직관적인 Cypher 문법으로 고속 조회합니다.

// Neo4j Cypher Query (친구의 친구 추천)
MATCH (u:User {name: '홍길동'})-[:FRIEND]->(f:User)-[:FRIEND]->(fof:User)
WHERE NOT (u)-[:FRIEND]->(fof) AND u <> fof
RETURN fof.name AS recommendation, count(*) AS mutual_friends
ORDER BY mutual_friends DESC LIMIT 5;
