🍃 NoSQL 4대 데이터 모델 심층 비교 & 쿼리 가이드

문서(Document), 키-값(Redis TTL), 와이드 컬럼(Cassandra CQL), 그래프(Neo4j Cypher)의 문법과 실무 모델링 분석

📊 1. NoSQL 4대 유형별 구조 매트릭스

1. Document Store

MongoDB

JSON/BSON 가변 구조 문서 저장. 중첩 객체와 배열 지원이 뛰어나며 RDBMS의 가장 범용적인 대안.

2. Key-Value Store

Redis

Key-Value 1:1 매핑. 인메모리 초고속 읽기/쓰기와 TTL 기반 자동 세션 만료 및 캐싱 특화.

3. Wide-Column Store

Cassandra

행(Row)마다 동적인 컬럼 집합. 파티션 키 기반의 대규모 분산 쓰기 및 IoT 시계열 데이터 최적화.

4. Graph Database

Neo4j

노드와 간선(관계)을 물리적 포인터로 연결하여 다단계 관계 탐색을 JOIN 없이 고속 해결.

💡 2. NoSQL 4대 모델별 실제 쿼리 문법 & 심층 해설

1. Document Store : MongoDB 가변 JSON

의류, 전자기기 등 카테고리마다 스펙 속성이 달라도 테이블 변경 없이 바로 저장합니다.

{
  "_id": ObjectId("64f8a1..."),
  "name": "맥북 프로 16인치",
  "specs": { "chip": "M3 Max", "ram_gb": 64, "ssd_tb": 1 },
  "tags": ["apple", "macbook", "developer"]
}

2. Key-Value Store : Redis 로그인 세션 & TTL 자동 소멸 원리

• TTL(Time To Live)이란?: 데이터의 유효 수명(초 단위)입니다. EX 3600을 주면 1시간 뒤 Redis가 메모리에서 해당 키를 백그라운드에서 자동 삭제(Eviction)하여 메모리 누수를 방지합니다.
• 세션 연장(Sliding Session): 유저가 마우스를 움직이거나 API를 호출할 때마다 EXPIRE 명령으로 1시간을 다시 리셋합니다. 

// 1. 세션 생성 시 1시간(3600초) TTL 설정
SET user:session:tk_99a8b1 "{\"userId\": 101, \"role\": \"ADMIN\"}" EX 3600

// 2. 남은 유효 시간 확인 (초 단위 반환)
TTL user:session:tk_99a8b1 ➔ (integer) 3540 (59분 남음)

// 3. 사용자가 활동할 때마다 세션 1시간 연장 (슬라이딩 세션)
EXPIRE user:session:tk_99a8b1 3600

3. Wide-Column : Cassandra CQL (Cassandra Query Language) & 시계열

• CQL이란?: SQL과 문법이 비슷하지만 JOIN과 외래키가 없는 분산 DB 전용 쿼리 언어입니다.
• 파티션 키 vs 클러스터링 키: PRIMARY KEY (sensor_id, recorded_at)에서 sensor_id는 수백 대의 분산 노드 중 어느 서버에 저장할지(해시)를 결정하고, recorded_at은 해당 노드의 디스크 안에서 시간순으로 정렬(Clustering)해 둡니다. 따라서 초당 수만 건의 센서 로그를 테이블 락(Lock) 없이 분산 쓰기할 수 있습니다. 

-- 1. IoT 센서 시계열 테이블 생성
CREATE TABLE factory_iot_metrics (
    sensor_id text,           -- 파티션 키 (어느 DB 서버 노드로 갈지 분산)
    recorded_at timestamp,    -- 클러스터링 키 (디스크 내에서 최신순 정렬)
    temperature double,
    humidity double,
    PRIMARY KEY (sensor_id, recorded_at)
) WITH CLUSTERING ORDER BY (recorded_at DESC);

-- 2. 특정 센서의 최근 10개 온도 초고속 조회 (단일 디스크 순차 읽기)
SELECT * FROM factory_iot_metrics WHERE sensor_id = 'SENSOR-FACTORY-A1' LIMIT 10;

4. Graph Database : Neo4j Cypher 문법 기초 해설

• Cypher 문법의 핵심 (ASCII-Art 화살표):
노드는 소괄호 (u:User), 관계와 방향은 화살표 대괄호 -[:FRIEND]-> 로 직관적으로 그립니다.
(홍길동)-[:FRIEND]->(친구)-[:FRIEND]->(친구의 친구) 패턴을 매칭(MATCH)하여 복잡한 다단계 관계를 O(1) 포인터 추적으로 0.01초 만에 찾아냅니다. 

// Neo4j Cypher (친구의 친구 추천 쿼리)
// 1. 홍길동의 친구(f)가 맺은 또 다른 친구(fof)를 탐색
MATCH (u:User {name: '홍길동'})-[:FRIEND]->(f:User)-[:FRIEND]->(fof:User)

// 2. 이미 나와 친구이거나 본인인 경우는 제외
WHERE NOT (u)-[:FRIEND]->(fof) AND u <> fof

// 3. 가장 겹치는 친구(mutual_friends)가 많은 상위 5명 추천
RETURN fof.name AS recommendation, count(*) AS mutual_friends
ORDER BY mutual_friends DESC LIMIT 5;
