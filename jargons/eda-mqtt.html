📡 EDA (Event-Driven Architecture) & MQTT 비교

이벤트 기반 아키텍처의 비즈니스 예시 및 IoT 프로토콜 MQTT와의 결정적 차이점

💡 EDA (이벤트 기반 아키텍처) 백엔드 예시

사용자가 상품을 주문하면, 주문 서비스는 결제나 배송 완료를 기다리지 않고 OrderPlacedEvent를 발행한 뒤 즉시 200 OK 응답을 반환합니다.

[ 이벤트 분산 전파 흐름 ]
1. 🛒 주문 서비스 ➔ Kafka Topic orders.v1 에 이벤트 발행
2. 💳 결제 서비스 ➔ 이벤트를 수신하여 PG 승인 진행
3. 🚚 배송 서비스 ➔ 이벤트를 수신하여 상품 출고 지시
4. 📱 알림 서비스 ➔ 사용자 카카오톡/SMS 알림 발송

🆚 Enterprise EDA (Kafka/RabbitMQ) vs IoT MQTT 비교

Kafka / RabbitMQ (Enterprise EDA)

  • 주요 목적: 마이크로서비스 간 고성능 비동기 결합 해제 & 데이터 파이프라인.
  • 특징: 대용량 데이터 보관(영속성), 순서 보장, 파티셔닝 수평 확장.
  • 네트워크 환경: 클라우드/내부 데이터센터 고속 브로드밴드 네트워크.
  • 사용처: E-Commerce 주문/결제 이벤트, 금융 정산 데이터 스트리밍.

MQTT (IoT Message Queue)

  • 주요 목적: 대역폭이 좁고 유연하지 못한 경량 센서/기기 간 메시지 전송.
  • 특징: 패킷 헤더 크기가 매우 적음(2 Byte), QoS 레벨(0, 1, 2) 지원.
  • 네트워크 환경: 3G/LTE, 스마트홈 센서 등 불안정한 저대역폭 환경.
  • 사용처: 스마트 워치 심박수 전송, 스마트 팜 센서 데이터 수집.
