🌐 REST API vs GraphQL vs gRPC 프로토콜 비교

웹/모바일 프론트엔드 연동 및 MSA 백엔드 서비스 간 통신 프로토콜의 장단점 비교

📊 3대 API 통신 프로토콜 한눈에 비교

REST API

- 전송: HTTP/1.1 + JSON 텍스트
- 특징: 리소스(URI) 중심 설계. 오버패칭(Overfetching) 가능성 존재.
- 용도: 가장 범용적인 공공 API & 모바일 백엔드.

GraphQL

- 전송: HTTP POST 단일 엔드포인트 + JSON
- 특징: 클라이언트가 원하는 필드만 지칭하여 수신. Over/Underfetching 해결.
- 용도: 복잡한 프론트엔드 UI/클라이언트 요청 대시보드.

gRPC

- 전송: HTTP/2 + Protobuf 바이너리
- 특징: 초고속 직렬화 & 멀티플렉싱 스트리밍. 타입안전 코드 자동생성.
- 용도: MSA 백엔드 내부 고성능 통신.
