🌐 REST vs GraphQL vs gRPC 실무 시나리오 다이어그램 & 심층 비교

외부 오픈 API 결제 승인(REST), 모바일 종합 대시보드(GraphQL), 대규모 MSA 백엔드 다단계 RPC 파이프라인(gRPC)

🎯 1. 3대 프로토콜 구체적 실무 적용 시나리오 & 페이로드 분석

1. REST API 시나리오 : 쇼핑몰 ➔ 토스페이먼츠/PortOne 외부 결제 승인 연동 범용성 / 방화벽 호환 / 표준 HTTP

배경: 전 세계 수만 개의 쇼핑몰 백엔드가 토스페이먼츠 결제 서버와 통신할 때, 별도의 전용 바이너리 라이브러리 설치 없이 표준 HTTP 클라이언트(WebClient, cURL, axios)만으로 즉시 연동되어야 합니다.

1. 쇼핑몰 서버 ➔ POST https://api.tosspayments.com/v1/payments/confirm
• Header: Authorization: Basic dGVzdF9za18..., Content-Type: application/json
• Body: {"paymentKey": "pk_99x81a", "orderId": "ORD-2026-0818", "amount": 50000}
2. 토스 결제 서버 ➔ 카드사 전산 승인 처리 후 ➔ HTTP 200 OK JSON 응답
• Response: {"status": "DONE", "approvedAt": "2026-08-18T16:50:00+09:00", "method": "CARD"}
💡 왜 REST인가?: 표준 HTTP 상태 코드(200 OK, 400 Bad Request, 401 Unauthorized), 방화벽 통과 용이성, 그리고 누구나 학습 비용 없이 즉시 연동 가능한 압도적 범용성을 제공합니다.
2. GraphQL 시나리오 : 배달의민족/인스타그램 모바일 홈 화면 (복합 도메인 단일 쿼리) 네트워크 RTT 4배 절약 / 오버패칭 제거

배경: 모바일 앱 메인 홈 화면에 1) 내 닉네임, 2) 장바구니 수량, 3) 최근 배달 1건 상태, 4) 이벤트 배너를 표시해야 합니다. REST로는 4번의 네트워크 왕복(RTT)이 발생하지만, GraphQL은 단 1번의 쿼리로 필요한 필드만 조립하여 가져옵니다.

[클라이언트 전송 쿼리 : POST /graphql]

query {
  user { nickname, grade }
  cart { totalItemsCount }
  recentOrder(limit: 1) { restaurantName, status }
  banners { imageUrl }
}

[서버의 맞춤형 단일 응답 JSON]

{
  "data": {
    "user": { "nickname": "홍길동", "grade": "VIP" },
    "cart": { "totalItemsCount": 3 },
    "recentOrder": { "restaurantName": "맛있는치킨", "status": "배달중" },
    "banners": [{ "imageUrl": "https://cdn.shop.com/b1.jpg" }]
  }
}
💡 왜 GraphQL인가?: 모바일 LTE/5G 무선망 트래픽을 60% 이상 절감하고, 화면 렌더링에 필요한 모든 데이터를 1번의 HTTP 왕복으로 해결합니다.
3. gRPC 시나리오 : 쿠팡/배민 선착순 특가 주문 MSA 다단계 RPC 파이프라인 초저지연 2ms / 단일 TCP 멀티플렉싱 / Protobuf

실제 비즈니스 상황: 선착순 타임세일 발생 시, 주문 서비스(Order Service)는 1초 안에 재고 차감 ➔ 쿠폰 적용 ➔ 결제 승인 3단계 마이크로서비스 RPC를 동기식으로 초고속 연계 처리해야 합니다. 텍스트 JSON 파싱 부담 없이 HTTP/2 단일 TCP 파이프 위에서 바이너리 프레임으로 통신합니다.

[1단계: 재고 차감 RPC] Order Service ➔ InventoryServiceGrpc.deductStock()
• Proto Payload: [08 65 10 01] (itemId=101, qty=1, 단 4 Byte 바이너리)
• 성능: 단일 TCP 멀티플렉싱 스트림 #1 전송 ➔ 1.5ms 만에 재고 선점 완료
[2단계: 쿠폰 검증 RPC] Order Service ➔ CouponServiceGrpc.applyDiscount()
• Proto Payload: [08 E8 07 12 08 53 41 4C 45 32 30 32 36] (userId=1000, code="SALE2026")
• 성능: 동일 TCP 멀티플렉싱 스트림 #2 전송 ➔ 1.0ms 만에 5,000원 할인 확정
[3단계: 결제 승인 RPC] Order Service ➔ PaymentServiceGrpc.processInternalPay()
• Proto Payload: [0A 0A 4F 52 44 2D 31 30 31 10 D0 B2 02] (orderId="ORD-101", amount=45000)
• 성능: 스트림 #3 바이너리 처리 ➔ 2.5ms 만에 최종 결제 완료 (전체 파이프라인 단 5ms 소요!)
⚡ CPU 파싱 오버헤드 0%
JSON 영문 문자열 파싱 없이 메모리 버퍼를 직접 역직렬화하여 초당 수만 건 처리
🔄 단일 TCP 연결 재사용
HTTP/2 멀티플렉싱으로 매 요청마다 TCP/TLS 3-way 핸드셰이크를 하지 않고 영구 파이프 유지
