🌐 REST API vs GraphQL vs gRPC 프로토콜 심층 비교

오버패칭 문제 해결(GraphQL), 바이너리 고속 통신(gRPC), 가장 범용적인 자원 기반 통신(REST)의 실제 요청/응답 예시

📊 3대 API 통신 프로토콜 실제 요청 & 응답 코드 예시

1. REST API (HTTP/JSON)

특징: URI로 자원을 명시하고 HTTP 메서드로 행위 정의. 모바일에서 닉네임 1개만 필요한데도 모든 필드가 다 내려오는 Overfetching 발생. 

// GET /api/v1/users/101
// [응답] 불필요한 필드까지 전부 반환
{
  "id": 101,
  "nickname": "길동이",
  "email": "hong@test.com",
  "address": "서울시 강남구...",
  "zipCode": "06012",
  "createdAt": "2026-01-01"
}

2. GraphQL (단일 엔드포인트)

특징: 클라이언트가 쿼리문에 "정확히 원하는 필드(nickname)"만 지칭하여 수신. Overfetching/Underfetching 완벽 해소. 

# POST /graphql
query {
  user(id: 101) {
    nickname # 닉네임만 요청!
  }
}

# [응답] 요청한 필드만 정확히 반환
{
  "data": {
    "user": { "nickname": "길동이" }
  }
}

3. gRPC (HTTP/2 Protobuf)

특징: 텍스트 JSON 대신 이진(Binary) 압축 데이터를 HTTP/2 멀티플렉싱으로 전송. MSA 백엔드 간 초저지연 내부 통신에 최적화. 

// IDL: user.proto 정의
service UserService {
  rpc GetUser (UserReq) returns (UserReply);
}

// [네트워크 전송]
// 단 12 Byte 초소형 바이너리 스트림
// 0A 07 EA B8 B8 EB 8F 99 EC 9D B4...
