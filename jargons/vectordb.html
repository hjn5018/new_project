📐 VectorDB, pgvector 하이브리드 JOIN & RAG 프롬프트 조립

SQL 관계형 데이터와 벡터 검색의 단일 JOIN 처리 원리 및 검색된 문맥(Context)의 LLM 프롬프트 결합 메커니즘

🗄️ 1. [핵심 질문 해결] pgvector에서 SQL 테이블과 벡터 검색을 JOIN한다는 것은?

전용 VectorDB(Pinecone 등)는 오직 벡터만 저장할 수 있어서, "재고가 남아있고 5만원 이하인 의류 상품 중 유사한 것"을 찾으려면 RDBMS와 VectorDB를 2번 조회하여 백엔드에서 조합해야 했습니다.
하지만 pgvector(PostgreSQL 확장)를 사용하면, 일반 SQL 조건(WHERE 카테고리='의류' AND 재고 > 0)과 벡터 코사인 유사도 정렬을 단 1개의 SQL 쿼리로 JOIN하여 즉시 해결합니다! 

-- [pgvector 하이브리드 JOIN 쿼리 예시]
SELECT 
    p.id, 
    p.name, 
    p.price, 
    p.stock_quantity,
    1 - (e.embedding <=> '[0.012, -0.043, ...]') AS semantic_similarity
FROM products p
JOIN product_embeddings e ON p.id = e.product_id
WHERE p.category = 'CLOTHES'       -- 1) 일반 SQL 조건: 의류 카테고리
  AND p.stock_quantity > 0          -- 2) 일반 SQL 조건: 재고 있는 상품만
  AND p.price <= 50000              -- 3) 일반 SQL 조건: 5만원 이하
ORDER BY e.embedding <=> '[0.012, -0.043, ...]' ASC -- 4) 의미적 유사도 순 정렬!
LIMIT 5;
