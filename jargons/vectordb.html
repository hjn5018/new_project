자연어의 의미(Semantic)를 고차원 부동소수점 벡터로 수치화하고 유사도를 계산하여 LLM의 환각을 방지하는 원리와 구조

💡 1. VectorDB의 3대 핵심 기초 원리

🧠 고차원 임베딩 & 코사인 유사도

• 고차원 벡터(High-dimensional Vector): 텍스트 문장을 인공지능 모델(text-embedding-3)을 통과시켜 1,536개의 실수 배열([0.021, -0.045, ...])로 변환한 것입니다.
• 코사인 유사도(Cosine Similarity): 단어의 단순 일치가 아닌 두 벡터 간의 사잇각(방향)을 계산하여, "강아지"와 "댕댕이"처럼 글자가 달라도 의미가 같으면 0.95 이상의 높은 유사도를 도출합니다.

🗄️ pgvector vs ChromaDB 차이

• pgvector (PostgreSQL 확장): 기존 RDBMS에 벡터 인덱스(HNSW / IVFFlat)를 추가하여 일반 SQL 테이블(회원, 주문)과 벡터 검색을 단일 DB 트랜잭션으로 JOIN 가능.
• ChromaDB: 파이썬 기반 AI 개발 및 프로토타입에 매우 가볍게 연동 가능한 오픈소스 임베딩 전용 데이터베이스.

📊 2. RAG (검색 증강 생성) 5단계 연동 시각 파이프라인

LLM은 회사의 최신 사내 규정이나 비밀 문서를 학습하지 못했습니다. RAG는 사용자의 질문과 가장 유사한 사내 문서를 VectorDB에서 먼저 찾아서 프롬프트에 주입(Injection)해 답변을 생성시킵니다.

💻 4. pgvector 실제 PostgreSQL 쿼리 문법

-- pgvector 확장 활성화 및 1536차원 벡터 컬럼 테이블 생성
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE document_embeddings (
    id SERIAL PRIMARY KEY,
    content TEXT,
    embedding vector(1536) -- OpenAI text-embedding-3-small 벡터
);

-- 사용자 질문 벡터와 가장 가까운 코사인 유사도 Top 3 문서 고속 검색 (<=> 연산자)
SELECT id, content, 1 - (embedding <=> '[0.012, -0.043, ...]') AS cosine_similarity
FROM document_embeddings
ORDER BY embedding <=> '[0.012, -0.043, ...]' ASC
LIMIT 3;
