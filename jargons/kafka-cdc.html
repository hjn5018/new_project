🌱 1. [초보자 필독] CDC가 왜 필요한가요? (이중 작성의 악몽)

❌ 전통적인 방식: 앱에서 직접 2군데 쓰기 (Dual Write 문제)

회원이 닉네임을 변경할 때 백엔드 스프링 앱에서 1) MySQL UPDATE ➔ 성공 후 2) Elasticsearch 색인 API 호출 ➔ 네트워크 장애로 실패! 가 발생하면, DB에는 새 이름이 있는데 검색창에는 옛날 이름이 뜨는 치명적 데이터 불일치가 발생합니다.

✅ CDC 방식: DB의 'CCTV 일기장'을 감시하기

앱은 오직 MySQL DB에만 평소처럼 저장하고 끝냅니다. 대신 CDC 엔진(Debezium)이 DB의 변경 로그(Binlog/WAL)를 실시간으로 테일링(훔쳐보기)하여 Kafka 이벤트로 발행해 Elasticsearch, Redis, Snowflake로 안전하게 자동 배달합니다.

📖 3. [용어 사전] CDC 파이프라인 필수 핵심 용어 해설

📘 Binlog (Binary Log)
MySQL이 데이터 추가/수정/삭제 등 테이블 변경 사항을 시간순으로 디스크에 기록하는 이진 로그 파일(일기장).
📘 WAL (Write-Ahead Logging)
PostgreSQL이 실제 데이터 페이지를 디스크에 쓰기 전에 트랜잭션 무결성을 위해 변경 내역을 먼저 기록하는 로그 파일.
🔍 로그 테일링 (Log Tailing)
리눅스의 tail -f 명령어처럼, 파일 끝에 실시간으로 새로 추가되는 로그 라인을 대기하며 지속적으로 읽어내는 기법.
📬 Kafka Topic
Kafka 안에서 데이터가 주제별(예: dbserver1.users)로 분류되어 분산 저장되는 메시지 채널.
📦 Apache Avro
JSON보다 훨씬 용량이 작은 바이너리 직렬화 포맷. 데이터 스키마(형식)를 중앙 Registry에 보관하여 네트워크 전송량을 80% 압축.
🎯 Target Sinks (싱크)
Kafka Topic에 모인 변경 데이터를 최종적으로 빨아들여 저장하는 목적지 시스템들 (Elasticsearch, Redis, S3 등).
❄️ Snowflake & DW (Data Warehouse)
DW(데이터 웨어하우스)는 기업의 방대한 데이터를 집계/분석하는 빅데이터 저장소이며, Snowflake는 가장 대표적인 클라우드 기반 초고속 분산 DW입니다.
