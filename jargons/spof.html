💥 SPOF (Single Point of Failure, 단일 장애점)

단 하나라도 고장나면 전체 서비스가 마비되는 치명적 아키텍처 결함과 다중화(Failover) 해결책

📚 SPOF 실무 주요 예시 및 해결 방안

  • 1. 단일 데이터베이스 (Single RDBMS Master)
    - 문제: DB Master 인스턴스가 다운되면 전체 서비스의 쓰기/읽기 트랜잭션이 전면 중단됨.
    - 해결책: Multi-AZ 복제 및 AWS RDS / GCP Cloud SQL의 **Automatic Failover(자동 승격)** 기능 적용.
  • 2. 단일 API Gateway 또는 단일 Nginx
    - 문제: 프론트엔드와 백엔드 사이의 단일 Nginx 인스턴스가 다운되면 모든 백엔드 서버가 살아있어도 접속 불가.
    - 해결책: GCP Cloud Load Balancing / AWS ALB 등 관리형 다중화 로드밸런서 배치.
  • 3. 단일 세션 스토어 (Single In-Memory Redis)
    - 문제: 단일 Redis 인스턴스 장애 발생 시 모든 사용자의 로그인 세션 및 대기열 정보 유실.
    - 해결책: Redis Cluster 또는 Redis Sentinel (Master-Replica + Failover) 구조 구축.
